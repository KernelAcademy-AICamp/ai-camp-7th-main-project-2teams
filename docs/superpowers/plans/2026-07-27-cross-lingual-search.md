# 한/영 교차언어 검색 개선

**상태**: 구현 롤백됨. 계측 자산(골든셋)과 사전 확장만 유지. 재착수 대기.
**작성일**: 2026-07-27
**관련**: PR #319, `front/lib/search-alias.ts`, `front/eval/search-golden.json`

---

## 1. 문제

한글 쿼리로 영문 문서를, 영문 쿼리로 한글 문서를 못 찾는다.

원인은 **임베딩 입력이 한 언어로만 채워지는 구조**다. `app/api/bookmarks/route.ts`의 strong 경로는
`` `${title}\n${content}` `` 를 임베딩하므로, 영문 페이지는 벡터가 통째로 영어 공간에 놓인다.
태깅은 병렬로 돌지만 그 결과가 임베딩 입력에 들어가지 않아 한글 신호가 하나도 없다.

weak 경로(`buildWeakEmbeddingText`)만 `generateWeakSummary`의 한국어 요약이 우연히 브릿지 역할을 한다.

## 2. 실측 (2026-07-27, text-embedding-3-large, 라이브 `match_bookmarks`)

### 2-1. 브랜드 축 — 사전이 실제로 필요한가

DB 전체 1039건(사용자 3명)의 태그 380종을 전수 조사해 검증.

| 조건 | 결과 |
|---|---|
| 검증 가능한 31개 alias 키 | 16개가 사전 없이는 top-10 실패 (14개는 top-60 미진입) |
| 사전 확장 후 | 31개 전부 top-3 진입 |

**측정 함정**: 한글 음차와 원어가 같은 문서에 병존하면 하이브리드 RPC의 trigram이 한글 쿼리를
직접 잡아 "사전 불필요"로 잘못 보인다. 병존 문서를 제외해야 교차언어 성능이 드러난다.
(1차 측정에서 "대부분 불필요"라는 반대 결론이 나왔던 원인 — `search-alias.ts` 주석에 기록)

### 2-2. 개념어 축 — 골든셋 `cross-lingual-concept` (n=6)

기존 `cross-lingual` 5건은 전부 사전 등재 브랜드 단독 쿼리라 사전 밖 영역을 재지 못했다.
사전으로 못 잡는 개념어를 양방향으로 측정하는 카테고리를 신설(b21~b24 추가, b9·b10 재사용).

| 구현 상태 | overall | concept |
|---|---|---|
| **없음 (현재)** | **0.8125** | **0.333 (2/6)** |
| 브랜드 앵커 | 0.844 | 0.500 (3/6) |
| 앵커 + 이중언어 요약 | 0.875~0.906 | 0.667~0.833 |

현재 성공 2건은 b24(incident response↔장애 대응)·b10(vector search↔pgvector) — 3-large가
자력으로 잡는 범위다. 나머지 4건은 반대 언어 신호 없이는 전멸한다.

### 2-3. 비용 (실측 토큰 기반)

| 항목 | 토큰 |
|---|---|
| `generateBilingualSummary` | input 120 / output 22 |
| 임베딩 입력 (요약·앵커 추가분) | +30 |

단건 저장당 **+$0.00012 (+21.7%)**. 증가분의 74%가 보강 재임베딩(전체를 다시 임베딩하므로),
26%가 요약 LLM. 저장 응답시간은 불변(`after()`로 응답 경로 밖 실행).

## 3. 롤백 사유

구현은 목표를 달성했으나(concept 0.333 → 0.833) 되돌렸다.

**임베딩 입력에 LLM 생성 텍스트가 들어가면서 골든셋이 결정적이지 않게 됐다.**

- 같은 코드 2회 실행에 concept 0.833 / 0.667로 흔들림
- 원인 확인: 같은 입력 5회 반복 호출 시 b23 요약이 **2종으로 갈림**(b21·b22는 1종으로 안정)
  ```
  A: 'Sharing methods to establish a retrospective culture.'
  B: 'Learn how to establish a culture of retrospectives.'
  ```
  쿼리 `team retrospective culture`에 대해 A는 어구가 연속돼 유사도가 높고, B는 어순이 달라 낮다.
  b23이 relevance floor 경계에 있어 이 차이가 통과/실패를 가른다.
- 결과적으로 게이트를 관측 하한까지 낮춰야 했고, **회귀 감지력이 도입 전보다 떨어졌다.**

`temperature: 0`으로는 부족하다. gpt-4o-mini는 완전 결정적이지 않다.

## 5. 재착수 시나리오

### 선행 조건 (필수)

**S1. 골든셋에 요약 고정값 박기** ★
`search-golden.json`의 각 북마크에 `ko_summary`/`en_summary` 필드를 추가하고, 평가 시 LLM을
호출하지 않고 그 값을 쓴다.
- 결정성 완전 복구. 평가 1회당 LLM 호출 24회 제거 → 실행 비용·시간도 감소
- `generateWeakSummary`(weak 경로)도 함께 고정해야 한다 — 아니면 변동 요인이 절반만 제거됨
- 고정값은 현 프롬프트로 1회 생성 후 사람이 검수해 박는다(모델이 바뀌어도 골든셋은 불변이어야 함)

**S4. 요약 생성 품질을 별도 테스트로 분리**
S1이 덮지 못하는 축. `generateBilingualSummary`만 검증한다.
- 알려진 페이지 N건: ko/en 둘 다 비어있지 않은지, 언어가 실제로 한/영인지, 길이가 상한 내인지
- 모르는 페이지(`example.invalid`): 빈 값 반환하는지 (환각 방지 회귀 가드)
- 존재·형식 검사라 내용 변동에 둔감 → 결정성 불필요

### 본 구현 (S1·S4 완료 후)

**A. 브랜드 앵커** — `buildBrandAnchor(title, url)`
title·URL에서 사전 등재 브랜드를 찾아 `"영문 한글"` 병기 문자열을 만들어 임베딩 입력 앞에 둔다.
- 사전 조회뿐이라 추가 LLM 호출·지연 없음
- 한글은 토큰 정확일치(조사 제거 포함) — `토스트`가 `토스`로 오매칭되는 것 차단
- 영문은 단어경계 정규식 + 등록 도메인 라벨 정확일치
- 커버리지: 브랜드 축만 (concept 0.333 → 0.5)

**B. 이중언어 요약** — `generateBilingualSummary({title, url})`
한/영 한 문장씩 생성해 임베딩 입력에 포함. `content` 미사용이라 본문 파기 규약과 무관.
- **반드시 `after()`로 응답 경로 밖에서 실행** (저장 응답시간 불변 제약)
- 모르는 페이지는 빈 값 degrade
- 커버리지: 개념어 축 (concept 0.5 → 0.833)

**C. 적용 범위 주의사항**
- POST / import / PATCH / reembed / 골든셋 평가 **전 경로에 동일 규약** 적용
- PATCH에 앵커를 안 붙이면 description 수정만으로 앵커가 소실돼 검색이 조용히 퇴화한다
- weak 경로도 포함하되 태그는 유지 — weak의 유일한 의미 신호다
- 임베딩 입력 규약이 바뀌므로 `scripts/reembed.ts` 전량 재실행 필요

### 보조 (독립적으로 가치 있음)

**S5. 골든셋 표본 확대**
현재 `cross-lingual-concept` n=6이라 1건이 0.167을 움직인다. n=12~15로 늘리면 민감도가 절반 이하.
`weak-vector` n=3 문제(보강 효과 판정 불가)도 함께 해소된다.
b23은 고정하더라도 floor 경계 케이스라 다른 변경에 쉽게 뒤집힌다 — 표본 확대가 필요한 이유.

### 검토했으나 채택하지 않음

| 안 | 사유 |
|---|---|
| N회 반복 후 중앙값 | 통계적 완화일 뿐 결정성 미복구. 실행 비용 3~5배 |
| 변동 폭 측정해 `평균−2σ`로 게이트 설정 | S1을 못 쓰는 경우의 차선 |
| 본문을 한국어 요약으로 치환 | 한 방향(영문 쿼리)을 희생 |
| 듀얼 벡터(`embedding_ko`/`embedding_en`) | 임베딩·스토리지·인덱스 2배, 스키마+RPC 개편 |
| 다국어 특화 모델 교체(bge-m3 등) | A51에서 bge-m3 롤백 이력 + 3-large 전환 직후 |
| 저장 경로 동기 실행 | 저장 응답시간 증가 — 제약 위반 |
| 유저 기입 `description` 번역·증강 | 원문 보존 요구 |

## 6. 미해결 이슈

| # | 이슈 | 비고 |
|---|---|---|
| 1 | `import` 경로 이중언어 보강 | 대량 LLM 호출 TPM 페이싱 설계 필요 |
